# 實體表單引導 Form Guide Studio

把紙本表單變成看得懂的線上引導。標註哪裡要填、怎麼填、哪些格子不是你的事，
支援多語切換、學號自動推導、模擬填寫成品，並可匯出 PDF、圖片與 QR 碼。

沒有伺服器，沒有資料庫，沒有帳號。整個系統就是一份可以放在任何靜態主機上的網頁。

**線上正式站**：<https://billy85276.github.io/form-guide-studio/>
**原始碼**：<https://github.com/Billy85276/form-guide-studio>

## 為什麼需要這個

站在櫃檯前拿著一張三聯複寫單的人，通常同時卡在四件事上：

- 系所要填簡稱「資網系」還是全稱「資訊網路工程系」
- 三聯是不是每一聯都要寫，還是有一聯是別人填的
- 這格要打勾、畫圈，還是寫正字
- 那個紅色的圈是幹嘛的，我可以碰嗎

這些問題紙上都沒寫，承辦人得一天回答二十次。這套系統把答案標在照片上，掃一次 QR 就看得到。

## 三個核心功能

**視覺引導**　在 1:1 的表單照片上疊出呼吸閃爍的標記。點哪裡看哪裡，
每一格寫清楚要填什麼、正確範例、以及最多人在哪裡出錯。承辦人負責的欄位標成灰色虛線，
學生一眼就知道不要碰。

**學號規則引擎**　編輯者用一張表定義規則，學生輸入學號就自動推導出學制、系所、入學學年，
並且附上「為什麼這樣猜」的理由。刻意不做黑箱，因為推導錯的資訊比沒有資訊更危險。

**模擬完成**　把輸入的內容以手寫字型、微傾斜、藍色墨水感渲染回表單，
還會自動畫勾與紅色刪除斜線。學生拿著螢幕照抄就行。
所有模擬產出都會燒入「模擬示範 SAMPLE」浮水印，避免被誤當成真的單據。

## 怎麼使用

### 我是編輯者，我要做一份新的引導

1. 打開 <https://billy85276.github.io/form-guide-studio/>，按「建立新的引導」。
   不熟悉的話先按「看示範：暑修繳費單」，照著那份範例的做法比較容易上手。
2. 到「聯與資料」分頁上傳表單照片。如果一張照片裡有兩三聯（複寫單常見），
   用「切成幾聯」把它切開，這樣學生就不用對著一張塞滿三份表格的圖片找自己那一份。
3. 到「標註」分頁，在照片上用滑鼠拖曳畫框（方框、圈選、底線、勾選框、箭頭都有），
   畫完在右邊填標題、完整說明、正確範例、常見錯誤。承辦人負責的欄位記得把「誰要填」
   設成「承辦人」，介面會自動標成灰色。
4. 想省時間就到「AI」分頁，貼上你自己的 Gemini 或 OpenAI 金鑰（去設定頁填一次即可），
   打字描述「分成幾區、每區要做什麼」，AI 會先畫出大部分的框，你再微調位置和文字。
5. 覺得同一個資料（例如姓名、學號）在好幾聯都要填，就去「欄位」分頁把它們接成
   同一個邏輯欄位，這樣學生輸入一次，模擬填寫時每一聯都會自動帶入。
6. 學號能推導出系所或學制的話，去「學號規則規則」分頁設一條規則，
   讀一下那頁最上面的警語再決定要不要設。
7. 做完到「分享匯出」分頁：
   - 想要一個網址讓學生掃 QR，看「上架分享」的三步驟說明
   - 想要一個純離線、不用網路的檔案，按「離線單檔 HTML」
   - 想要印出來貼在櫃檯，按「紙本」開啟列印，選「另存為 PDF」
8. **做完務必按「匯出封存 zip」存一份下來。** 你的資料只活在這台電腦的瀏覽器裡，
   清瀏覽器資料或換電腦就會消失，那個 zip 才是真正的備份。編輯臺右上角也有
   「綁定備份檔」，選一個放在雲端硬碟的檔案，之後每次修改都會自動同步進去，更保險。

### 我是學生，我掃了 QR

進來就會看到紙上所有該注意的地方都被標記起來，上面寫著這份表單有幾聯、
你要填幾格、承辦人填幾格。點任何一個標記看說明，或按「逐步精靈」一步一步被帶著填。
右上角可以切換語言。如果表單有設學號規則，輸入你的學號系統會自動幫你判斷學制系所。
填完想確認自己填對了，按「看填好的樣子」，畫面會模擬成手寫字回填到表單上給你對照。

## 學生端長什麼樣

掃 QR 進來的第一屏，紙上所有該注意的位置都已經標好，並告訴他「這份表單共 2 聯、你要填 12 處、承辦人填 4 處」。

- 點任何一個標記，圖片放大到那一格，下方跳出說明
- 或按「逐步精靈」，一步一步帶完
- 右上角切語言，支援繁中、英、越、日、印尼、泰、簡中
- 輸入學號自動判斷學制系所
- 一鍵切換「看填好的樣子」

## QR 碼與離線韌性

先講一個必須澄清的事實：**QR 碼塞不下這套東西**。
QR 版本 40、錯誤更正等級 L 的理論上限是 2953 位元組，
一張壓到 200 KB 的表單照片經過 base64 之後約 270 KB，差了快一百倍。
所以「把整份引導塞進 QR」在物理上不可能，任何宣稱做得到的方案都是錯的。

QR 只能存一段短字串，也就是一個網址。因此韌性不是來自 QR 本身，
而是來自那個網址背後有幾份備援。這套系統提供五層，越後面越硬：

| 層 | 機制 | 主站掛掉時 |
| --- | --- | --- |
| L1 | 主站，目前是 GitHub Pages | 失效 |
| L2 | 再部署一份到 Cloudflare Pages 之類的服務，紙上印兩顆 QR（選用，目前沒開） | 掃備用 QR 就能用 |
| L3 | PWA 離線快取 | 掃過一次的手機還打得開 |
| L4 | 單檔離線 HTML，圖片內嵌，可放隨身碟或用 LINE 傳 | 完全不需要網路 |
| L5 | 匯出的 A4 引導單本身就印了完整步驟 | 永遠有效 |

**目前只開了 L1**，這是你在 2026-09-02 自己決定的：GitHub Pages 一家夠用，
不想再多管一個 Vercel 帳號。如果之後真的想要 L2，作法是把同一份程式碼再部署一次到
Cloudflare Pages（或任何免費靜態主機），然後在編輯臺「分享匯出」分頁的備援網址欄填上去，
紙上就會多印一顆 QR。

L5 才是真正的答案。紙不需要網域，這也是為什麼列印版面被當成第一級產出，不是附屬功能。

## 你的資料放在哪裡

引導檔存在你自己瀏覽器的 IndexedDB 裡，我們沒有伺服器，看不到也備份不了。
清除瀏覽器資料或換一台電腦，資料就沒了。

對策有兩個，建議兩個都做：

1. **綁定備份檔**　編輯臺右上角，選一個檔案（放在雲端硬碟資料夾最好），
   之後每次修改都會自動寫進去。這需要 Chrome 或 Edge。
2. **匯出封存**　分享匯出頁下載一個 zip，裡面有 guide.json、每一聯的圖、每一步的特寫卡。
   那個檔案才是你真正的正本。

## AI 標註

上傳照片，用打字描述你要怎麼分區，AI 會先把大部分的框和說明生出來，你再微調。

金鑰存在你自己的瀏覽器，直接呼叫供應商的 API，不經過任何中繼伺服器。
這個設計讓帳單落在使用者自己頭上，所以這套工具才能免費開放給任何人使用。

支援 Google Gemini 與 OpenAI。**建議用 Gemini**，因為它是唯一一家在官方文件裡
明確定義標框座標格式的供應商，對「請框出學號欄位」這種任務準確度明顯較高。
座標約定是 `[ymin, xmin, ymax, xmax]`，正規化到 0 到 1000，注意 y 在前。

也可以一鍵把所有中文說明翻成其他語言，只翻還沒有譯文的欄位，人工改過的不會被蓋掉。

### 關於把金鑰放在瀏覽器

- 金鑰只存在使用者自己的裝置，不會傳到別的地方
- 建議到 Google AI Studio 幫金鑰加上網站來源限制，並在供應商後台設用量上限
- 不要在公用電腦使用，設定頁有清除鍵
- 如果這個網站被植入惡意程式碼，金鑰就會外洩。這是所有「金鑰放前端」做法共同的風險，
  我們的對策是把外部相依壓到最少，但無法宣稱風險是零

Google 官方文件警告「不要把 API 金鑰寫死在網頁或行動應用程式裡」。
那句話針對的是開發者把**自己的**金鑰包進程式碼發布出去，
不適用於這裡的「使用者自備金鑰」模式，兩者的風險承擔者完全不同。

## 處室內部檢視

有些註記只給承辦人看。設一組密碼，標註就能標成處室限定。

**這道密碼是前端 SHA-256 比對，懂技術的人打開開發者工具就能繞過。**
它的用途是避免學生誤看到內部註記造成混淆，不是資訊安全機制。
真正機密的內容的正解是不要放進這個系統，而不是替它加密。

## 開發

```bash
npm install
npm run dev      # 本機開發伺服器，有熱重載
npm run build    # 型別檢查 + 正式建置，push 前一定要先跑過
npm run lint     # oxlint
npm run preview  # 本機預覽 build 出來的 dist
```

需要 Node 22 以上。技術棧是 React 19、Vite 8、TypeScript 6、Tailwind CSS v4，
沒有用任何 UI 元件庫（沒有 shadcn、沒有 Radix），介面元件都手刻在
`src/components/ui.tsx`，總共不到兩百行，這是刻意的選擇，換掉它之前想清楚為什麼。

### 這個專案是怎麼做出來的

一個人（你）配合 AI 助手在一次對話裡從零生出來的，中間先跑過一輪並行研究
（技術選型、離線 QR 的實際物理限制、瀏覽器直連視覺 AI 的可行性、CJK 手寫字型），
再進入實作。沒有測試框架、沒有 CI 檢查（除了型別檢查），這是個人專案的正常規模，
不是疏漏。如果之後要加測試，`vitest` 是最省事的選擇（Vite 官方生態）。

### 專案結構

```
src/
  lib/
    types.ts       核心資料模型。座標一律 0~100 百分比，這是最重要的約定
    text.ts        多語文字解析與回退鏈
    rules.ts       學號規則引擎
    storage.ts     IndexedDB 讀寫、設定、圖片轉可攜格式
    image.ts       上傳壓縮、裁切、餵給 AI 的縮圖
    share.ts       分享連結壓縮編碼、離線韌性策略、處室密碼雜湊
    ai.ts          Gemini 與 OpenAI 的視覺標註與翻譯
    exporters.ts   Canvas 繪製、PNG、PDF、ZIP、單檔 HTML
    qr.ts          QR 產生
    factory.ts     建構函式與角色色票
    demo.ts        內建示範引導（暑修繳費單）
    ui-i18n.ts     介面文字字典，七種語言
  components/
    FormCanvas.tsx    把標註畫到照片上，檢視與編輯共用同一段程式
    LocalizedInput.tsx 多語文字輸入元件
    ui.tsx            所有基礎 UI 元件（按鈕、卡片、輸入框、彈窗）
  editor/          編輯臺，六個面板（標註/聯與資料/欄位/學號規則/AI/分享匯出）
  viewer/          學生端（總覽 + 逐步精靈 + 純文字版 + 列印版）
  pages/           首頁與設定頁
  App.tsx          路由，用 hash 不用 history（見下方原因）
```

### 三個不可動搖的約定，改之前先看 AGENTS.md

這三件事在 `AGENTS.md` 裡有更完整的說明，這裡只列重點：

1. **座標一律是相對百分比 0 到 100**，不是像素也不是 0 到 1。
   同一份標註要同時在手機、桌機、A4 紙上落在同一個位置，百分比可以直接餵給 CSS，
   混用兩套座標系是這類疊圖產品最經典的長期 bug 來源。
2. **路由用 hash 不用 history**，這樣同一份建置產物不管放在 GitHub Pages 子路徑、
   自己的網頁空間根目錄、學校內網資料夾，甚至用 `file://` 直接開啟，都不用改設定。
3. **建置產物必須是單一 JS 檔**（`vite.config.ts` 的 `codeSplitting: false`）。
   「下載離線版」是把目前頁面的 JS/CSS 抓下來內嵌成一份 HTML，一旦有分包
   離線版就會缺檔案開不起來。

還有一個容易忘記的坑：`import.meta.env.BASE_URL` 因為 `base: './'` 的關係是一個
相對路徑字串，不能直接跟 `location.origin` 字串相接（會拼出壞掉的網址）。
正確做法統一寫在 `src/lib/share.ts` 的 `currentSiteOrigin()`，需要「目前這個網站的
完整網址」一律呼叫它，不要自己重新拼一次。

## 部署

**目前的正式部署方式，也是唯一在用的方式**：

推到 GitHub 的 `main` 分支，`.github/workflows/deploy-pages.yml` 會自動：

1. `npm ci` 安裝相依
2. `npm run build` 建置
3. 把 `dist/` 上傳並發布到 GitHub Pages

大約一分鐘內新版本就會出現在 <https://billy85276.github.io/form-guide-studio/>。
不需要手動做任何事，包括第一次啟用 Pages（已經開好，來源設定是 GitHub Actions）。

想手動觸發一次部署（例如只改了 repo 設定沒改程式碼）：

```bash
gh workflow run deploy-pages.yml
gh run watch                       # 看即時進度
```

**如果之後想加開別的主機**（多一層離線韌性，見上面的韌性分層表）：

- **Cloudflare Pages**　建置指令 `npm run build`，輸出目錄 `dist`，接同一個 GitHub repo
  即可自動部署，設定完把網址填進編輯臺「分享匯出」分頁的備援網址
- **Vercel**　之前評估過但目前沒有在用（2026-09-02 決定只留 GitHub Pages）。
  如果要重新啟用，`npm run build` 產出的 `dist/` 可以直接匯入，不需要任何額外設定，
  因為 `vite.config.ts` 的 `base: './'` 讓建置產物可以放在任何主機的任何路徑
